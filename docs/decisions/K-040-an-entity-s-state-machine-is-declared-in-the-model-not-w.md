# K-40 — An entity's state machine is declared in the model, not written a second time as guards

**An entity's lifecycle — its states, and which operation moves between them — is declared beside its entities and operations, and the compiler holds it to both.** This **reverses a position published in `apps/docs/concepts/model.md`**, which listed state machines under *Prose* and said: *"if you find yourself inventing a way to declare a state transition, the boundary has slipped."* The codebase had already falsified it. Six entities across four engines and two demos carried a `status` enum, and every one described its transitions a second time as hand-written guards in operation bodies — `requireStatus(row, 'planned', 'in_progress')` at six call sites in workorder, nine in booking — held to the enum by nothing; `engine-booking` wrote its seven-value state *set* out twice, as two independent `z.enum` literals in `entities.ts` and `index.ts`. The boundary was not holding, it was being redrawn at every call site. A lifecycle declares **only** the state set, the edges, which operations are legal-but-inert in a state (`allow`), which states admit substates (`extensible`, K-17's missing mark) and which are terminal. It declares **no** action, condition, effect, timer or expression language — the moment an edge carries a condition this is BPMN in TypeScript, which the plan's Workflows row already refused. Durable execution stays where it is (outbox → `_substrat_deliveries` → sweeper); a lifecycle never says *when* and never runs anything. **Guards are NOT re-declared here**: K-38 already wires them in the manifest as `{ before, predicate, config }` with the kernel evaluating them before the guarded operation, and every edge names its operation, so the emitters *join* the two rather than making anyone write it twice. The evaluator is kernel-layer, not an engine — it owns no domain entities — and is interpreted in-process (an object lookup), while the artifacts that must cross a boundary or be frozen are emitted: `model.json` for review, an XState v5 config for diagrams and as a test oracle. `engines/workorder` is the adopter; booking, protocol, invoicing, manyfold and shop are the queue.

## Why

The rule the old position was protecting is real and is now protected explicitly rather than by discouragement — a lifecycle cannot express behaviour, only legality. What the old position could not protect against was the duplication it caused: with nowhere to declare the machine, every module invented its own guard, and two demos drifted off the platform error contract entirely (`demos/shop` threw a bare `Error`, returning a 500 where every engine returns a 409). Three further consequences made the declaration overdue rather than optional. **K-17 was unbuildable**: kernel-design §7.5 specifies substates as *"the engine's state-machine declaration marks which states admit substates"*, and `substates` appeared in that document and in zero `.ts` files, because there was no declaration for the mark to live on. **Guards could not bind to a transition**: `manifestGuard.before` names an operation, and the FSM survey's *"obligatorisk för status"* is a property of an edge that did not exist. **A widened state machine was invisible in review**: adding a transition was a one-line change to an `if`, where `lint:permissions` exists precisely because widening a role must appear in a diff — and widening a lifecycle is no less consequential. Declaring it makes all three mechanical: the machine emits into `model.json`, CI re-emits with `--check`, and the artifact is what a human reads.
