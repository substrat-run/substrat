# K-32 — global is a first-class jurisdiction, and the storable vocabulary (eu/us/global) is…

**`global` is a first-class jurisdiction, and the storable vocabulary (`eu`/`us`/`global`) is complete before its enforcement is; the provisioning boundary gates what it cannot yet honour** (refines K-7/K-30). Prompted by setting up the real environment on the `substrat.net`/`substrat.run` account: jurisdiction is fixed at provisioning and a DO can never relocate (K-7), so the vocabulary a scope can be assigned must be final BEFORE the first production scope exists — widening what can be *stored* later is a data migration, widening what is *accepted* is a one-line change. Two findings forced the shape. **First, jurisdiction was recorded but never enforced**: the only DO id minting is `idFromName(scopeId)` (`adapter-cloudflare/host.ts`), with `newUniqueId`/`ns.jurisdiction(...)` appearing nowhere but a deferral comment — so `eu` on a scope today is a directory string that moves no storage and terminates no TLS. **Second, the old `z.enum(['eu']).nullable()` made `null` mean both "unconstrained" and "nobody decided"**, and the provisioning input defaulted to it, so absence silently became a residency posture. So: `jurisdiction = z.enum(['eu','us','global'])`, non-nullable, defaulting to `global` (the honest name for what every scope already is — no subnamespace, placed near first access); legacy `null` rows coerce to `global` on read. A separate `provisionableJurisdiction = z.enum(['global'])` gates the HTTP boundary — `eu`/`us` are refused with 400 until their enforcement (DO jurisdiction subnamespace, Regional Services) is bought and built, gated exactly as `STANDALONE`/`ALLOW_DEV_HEADER` are (K-31). Deriving `hostnameRegion` from the scope rather than accepting it (the "two values that must agree, supplied separately" the contract flags) is the natural next step and is deferred — it is not immutability-sensitive, so it need not land before provisioning

## Why

The distinction that matters: a value we can never rename must ship complete, but a guarantee we cannot yet honour must not ship at all. Conflating them is how a plan dependency (Regional Services, an Enterprise add-on — K-26/K-30/D-35) becomes a false residency claim answered in a DPA rather than at pricing. **`us` is not symmetric with `eu`** and the enum hides it: Cloudflare offers `eu` and `fedramp` as DO jurisdictions but no US subnamespace, so `us` is Regional Services plus a D1 location hint, a different mechanism behind the same word — worth recording so "deploy one EU and one US" is not mistaken for one mechanism applied twice. Cost was near zero because the columns were already nullable `TEXT` in inline DDL and the target account had no rows: **no SQL migration, no migration-checkpoint** — the change is a Zod widen, a default flip, two read-coercions, the boundary gate, and the console picker (which now shows `eu`/`us` disabled rather than hiding them, so the roadmap is visible where the choice is made). What this does NOT do: make `eu` real. A scope provisioned `global` today and needing `eu` later is still a migration — but now it is a migration between two *named* values a human chose, not a silent promotion of `null`, and the gate guarantees no customer is holding an `eu` scope that was never enforced
