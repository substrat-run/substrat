# D-54 — The generated vertical is the customer's code; the studio is a tool, not the author

> **Ratified 2026-08-19.** Transcribed from docs/design/builder-studio.md §13 during the Phase-2 log
> split, which found this decision built but never written into the log. The text is
> the author's; only the id is new.

**The generated vertical is the customer's code; the studio is a tool, not the author.** Export is available from day one rather than at offboarding, we hold the repo as custodian by arrangement (D-53), the model provider is a disclosed subprocessor the tenant may constrain, and ownership is never offered as an answer to the review question.

## Why

The honest description of the product is "a better-guardrailed agent than the one they would point at this themselves" — and each consequence is something that becomes expensive to retrofit once customers exist. The subprocessor point is the one with teeth: it converts the pluggable provider seam (D-50) from a portability nicety into the mechanism that answers a procurement objection by configuration — EU-resident inference, a vendor veto, or a self-hosted model — instead of by losing the deal.
