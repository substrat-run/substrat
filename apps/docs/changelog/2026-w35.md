# Week 35 · 24–30 August 2026

Forty-eight merges, most of them answering one question: **what does an HTTP
surface owe a client that is a program?** An agent retries faster than a person,
reads a status code before a sentence, and saves over a record it read a minute
ago without noticing. By the end of the week the surface every vertical gets for
free answers all three — a problem document, a free retry, a refused stale write —
and the checks an operation declares are driven by a kit rather than trusted.
Alongside that: two reads the kernel now owns, engines that parse on the way out,
and a new demo that puts an AI assistant on staff.

## The error a client gets is a document, not a sentence

Every surface answers `application/problem+json` ([#910]). Seven verticals, the
scaffold template and the control plane each used to carry a hand-rolled handler
that read a status out of an error's *prose* — `/not found/` → 404, `/out of
stock/` → 409 — and answered `{ error: "<message>" }`, while `/openapi.json` had
promised a problem document since the taxonomy landed. The patterns were not kept
as a fallback; the throw sites were typed instead. Seventy-three raw `new Error`
across the demos became `substratError(code, message, { reason })` — the platform
owns the code, the vertical owns the reason — and `@substrat-run/vertical-host`
exports `problemResponse`, the one-liner an `app.onError` should now be.

```json
{ "type": "https://substrat.net/errors/conflict", "title": "Conflict", "status": 409,
  "detail": "out of stock: SKU-14 — 2 available, 5 requested",
  "code": "conflict", "reason": "out_of_stock", "instance": "/api/op/shop/add-to-cart",
  "error": "out of stock: SKU-14 — 2 available, 5 requested" }
```

The `error` member is still there, deprecated, so a client reading it keeps
working. Read `code` and `reason`. A parse failure now carries its field-level
`errors[]` on both substrates ([#903]) — on Cloudflare it used to survive only as
JSON inside the message string, which is the shape that is structured in a
scenario test and bare in production.

**This one changes behaviour.** The host now parses a declared operation input
on every path in — HTTP, test, seed, schedule — before the guards and the handler
([#902]). Across the fleet the declaration was true about the *shape* and false
about the *parsing*: RallyPoint declared 32 inputs and parsed 2, the shop 14 and
0. A call that used to reach a handler with a malformed body now gets
`validation_failed` before the handler runs. A module passes
`operationInputs: operationInputsOf(ops)` beside its `operations`; handlers stop
hand-parsing.

## A retried write is free, and a stale one is refused

A client whose request times out does not know whether the work happened; it
retries, and there is a second work order. A client now sends a key it chose,
and the same key on the retry returns the first response instead of doing the
work again ([#908]):

```http
POST /api/workorders
Idempotency-Key: dispatch-4471
```
```http
200 OK
Idempotency-Replayed: true
```

Every operation on an unsafe method honours the header — nothing is declared,
because a retried write creating a second entity is a hazard on all of them. The
recording is written inside the operation's own transaction, so a failed request
is retried rather than replayed, and the same key on a *different* request is a
409.

The lost update is the opt-in half. An entity's version is the ULID of the last
event that touched it ([#904]) — `_substrat_outbox` had recorded it on every
mutation since it was written, and nothing had read it back. `ctx.versionOf(ref)`
returns it; there is no `_version` column, no trigger and no migration. On top of
that, an operation that is read-modify-write declares what it writes over
([#906]):

```ts
'callout/update-facility': {
  permission: { key: 'facility:manage', entity: 'facility', idFrom: 'facilityId' },
  concurrency: { over: 'facility', idFrom: 'facilityId' },
  http: { method: 'PATCH', path: '/facilities/{facilityId}' },
  …
}
```

One declaration, three consequences: every response carries the version as an
`ETag`, an unsafe method compares the caller's `If-Match` inside the transaction
and refuses a stale one with `precondition_failed` (412), and the generated
browser client remembers the tag a read handed back and sends it on the next
write — an app writes no header code.

## Two reads the kernel owns, and a fourth door into a scope

Reading `_substrat_outbox` for one entity was always a sanctioned projection;
what was missing was a supported shape, and five demos wrote the query by hand and
disagreed about the cursor. `readTimeline(ctx, ref, page)` and `readHistory`
are now kernel exports ([#911]) — the caller checks the permission, the kernel
walks — with the event ULID as the cursor, which is creation order and survives a
restore where a `rowid` does not.

The denial log got a reader ([#905]). Every enforced denial in production has
been recorded for a month; nothing read it. `listDenials` and `summarizeDenials`
serve it through the same audited delegation ladder as the table reads, the
control plane exposes it per scope, and the console shows it. Reading the denial
log is itself logged.

And a staff member can act as a principal with the real actor preserved
([#917]): `beginImpersonation` opens a read-only, fifteen-minute, admin-logged
session, and a stub obtained through it answers as that principal — through the
ordinary permission checker, with no override branch. **If your timeline or
audit screen renders events**, it will now see `impersonation: { session, by }`
on every event, history entry and denial row; `actor` stays the impersonated
principal, and the staff actor rides beside it.

## Every narrowed check is declared, and the kit drives it

The entity-check conformance kit reached the whole fleet. Booking, Meridian,
RallyPoint and the shop declared their operation surfaces ([#892]) — all 23
driven checks were already honoured, and the kit found its own limit: a narrowed
check behind a node gate is unreachable by a probe that holds nothing. Invites,
metering and Manyfold, the last three, moved from a grep over source text to a
declared surface ([#916]), and the follow-up fixed what only a declaration can
state exactly — a missing key in `manyfold/whoami` that hid a site manager's
chrome, and `narrows.unchecked` for an operation that genuinely checks nothing
([#921]).

Two declaration shapes were missing. A narrowed check may name several entity
types and the input schema says which — `entityFrom` ([#895]), where a red test
found that one timeline operation had served *two* types all along while its
declaration named one. And an engine that narrows to a ref the caller owns says
`refFrom` ([#897]): absence narrows to Meridian's `employee`, a noun it has never
heard of, so there is nothing for `entity` or `idFrom` to add. A kit option,
`coEntities`, drives an operation that names a second entity of its own kind — a
`merge` ([#945]).

The receipt exists now ([#899]): fourteen `CONFORMANCE.md` files, one per demo
and engine, gated by `pnpm lint:conformance --check` — 47 conformance pairs
driven across 41 narrowed checks, the six that cannot be driven named with
reasons. And a reminder of why the declaration is the thing that matters:
`workorder/start` declared `workorder:assign` while its handler checked
`workorder:report`, and the declaration is what every artifact reads ([#995]).

## Engines parse on the way out, and a bare catch is a lint error

"Parse, don't trust" was enforced in one direction. Return values crossing the
engine seam were trusted because TypeScript said so — and a raw `SELECT *` typed
by assertion publishes whatever the table currently holds, which is how a
vertical compiled against engine 0.3 and running against 0.4 gets *wrong data on
a screen* rather than a throw. Work orders established the pattern ([#912]):
`returns(schema, surface, value)` parses every published value with the schema a
composing vertical declares its `output` with, and `columnsOf(schema)` derives
each `SELECT` list, so a dropped column is a SQL error naming itself. Booking
([#942]), protocol ([#946]) and absence ([#949]) followed; invites, invoicing and
metering are still typed by assertion. Work orders also became fully composable
by call — `assignWorkOrder`, `startWorkOrder`, `reportTime` and `reportMaterial`
are in-scope functions now, not just operations ([#996]).

**This one will make an existing lint go red.** Boundary-lint **R7** ([#913]):
in module code, a `catch` whose `try` calls an engine in-scope function, outside
a `ctx.atomic` callback, is a violation — you are holding the engine's partial
writes and about to commit them. It ships as R7, not the R6 the design note had
pencilled in, because the no-clock rule took R6 first. There is deliberately no
`boundary-lint-allow` hatch for it.

## ticket0, and the owner seat

A new demo vertical: **ticket0**, an AI-assisted support desk — a chat widget a
customer embeds on their own site, an inbox for staff, a customer portal, and an
assistant that answers out of the tenant's own documentation ([#918]). The one
idea: the assistant is *staff*. It has an account and a role, so "may the AI
answer customers, or only draft for a human?" is not a setting — it is which
permission its account holds, and two seeded desks prove it with the same call.
It composes metering (an append-only, idempotent token ledger) and invites, and
deliberately not work orders.

It is deployable ([#922]) and live on this site — the widget is mounted on
[Ask the docs](/guide/support) ([#932]), and how to embed it, and what vouches
for a visitor, is written down ([#926]). A visitor's device, language and rough
location are normalised once, in the adapter, so the vertical never learns which
runtime it is on ([#992]). The first week in production found what a first week
finds: a merge could cross contacts and hand one contact's session token to
another's thread ([#919]); a desk with no owner hid its login ([#924]); the
knowledge base had no add form ([#931]); origins could not be managed ([#944]);
every crawler that ran `widget.js` opened a conversation ([#951]); and the
assistant's failures were invisible ([#993]).

One of those findings reached the platform. **A hosted vertical's owner seat is
now claimed by the first sign-in for fifteen minutes after provision, then only
by a claim link** ([#930]). Before, the seat was bound to whoever completed the
OIDC round-trip first, with no expiry — and a re-provision re-minted it, so a
sweep could hand a claimed instance to the next stranger. If you run an instance
that was provisioned earlier and never claimed, its window now reads as closed;
mint a claim link from the dashboard.

## Also landed

**The issuer** — `demos/auth-server` speaks OAuth 2.1 through
`@better-auth/oauth-provider`, which Better Auth 1.7 forces, and its registered
applications can be listed, edited and rotated; self-service sign-up exists and
defaults to off ([#907]). The login and consent pages it had always pointed at
now exist ([#900]).

**Scaffolding and the CLI** — `substrat push` from CI died on a config path it
resolved twice ([#927]) and then on a monorepo vertical's unbuilt workspace deps
([#928]); both are fixed in the CLI and the generated workflow. The permission
and API gates have a standalone form for a project outside the monorepo
([#950]). A fresh worktree inherits the env and secret files it needs to run
([#941]). `useAutoRefresh` in `@substrat-run/ui` states the revalidate-and-deny
contract — a screen that outlives a revoked grant refetches instead of showing
stale rows — and todo and the shop adopt it ([#948]).

**Docs** — this changelog section itself ([#914]); the todo app as the
walkthrough, with the concept, model and module pulled in as whole files at
build time so they cannot drift ([#947]); `ctx.grant` / `ctx.revoke` and
`demos/todo` named everywhere an agent decides how sharing works ([#940]); and
`pnpm lint:docs --check` now reaches both docs checkpoints instead of only the
last one ([#994]). Two commits landed without a PR: the platform's generated
deploy workflow for ticket0, added and then updated by the push itself.
