Binding invites: a `become` link can also bind its claimant to their own record (#1686).

A customer invite is not delegation. It does not hand someone a share of the inviter's authority. It binds the person who claims it to their own record: a contact, a customer, an employee. The rights that come with that record are declared in the vertical's model, reviewed at the permission checkpoint, and never carried by the link. The link names only which record.

- **The declaration.** An `ENTITY_GRANTS` shape gains an optional `bind: { permission }`. It is valid only on a `bootstrap` shape whose `holder` is the table form (`{ table, idColumn, principalColumn }`), and the permission must be a declared key that is not one of the shape's own current or retired keys. Whoever holds that ordinary key on a record may invite its person with a link, and may unbind them. The holder column should be one of the entity's erasure subjects, not an `erasable` field. A binding shape's keys are refused to every grant except the shape's own, as a `'grantee'` shape's are, so on such a record the column is what decides who holds them. `PERMISSIONS.md` gets a column for it, and the version-to-version diff says when a shape gains or loses a bind (`grantChanges[].bind`, and a holder note). Omitted when unset, so a registry that binds nothing keeps its digest.
- **The reconcile records it.** Each reconcile pass records the reached registry's binding shapes in the scope (holder column, bind key, current keys) beside the grantee keys, matching that registry exactly. The claim and an unbind read that record, never the vertical's code, so a scope not yet reconciled with a binding declaration binds nothing. The Cloudflare host now runs the pass for a registry with no shapes too, so a version that drops its last grantee or binding shape stops refusing direct grants and stops binding on that host as well.
- **The mint.** `principalBecomeCapabilityInput` takes an optional `bind: { entity }`. Besides the existing bound on the target, the host's bounded mint refuses with nothing written: `bind-not-declared` (no binding shape for that type in the scope's reconciled registry), `bind-record-missing`, `bind-record-bound` (the record already names a person; refused, never re-bound), and a `coverage` naming the bind key when the minter does not hold it on that record. The link carries the action in a new nullable column, `_substrat_capabilities.action` (JSON `capabilityAction`, `{ kind: 'bind', entity }`), which both adapters add to existing scopes on start. A `become` capability record carries it as `action`, so the operator's capability list and the console card show a bind link as one. `capability.become-minted` gains an optional `action` field.
- **The claim is one transaction.** The exchange judges the bind again before it takes the use: the binding still declared, the record there and naming nobody, the minter still holding the key on it. Any refusal is the exchange's one refusal (`null`) and leaves the link unspent. A link whose minter has lost the key, or left, is refused this way. After the use is taken, in the same transaction, the record's column is set to the claimant, the shape is granted (its marker and current keys), and a new kernel-authored event, `entity.holder-bound` v1, goes on the record's history with the capability as actor. A failure inside any of it rolls the use back too. The exchange's answer gains `bound: <entity>`.
- **The unbind.** A new bounded host verb, `unbindEntityHolderBounded(tenantId, scopeId, caller, entity)`, on `SqliteScopeHost` and `CloudflareScopeHost`. The caller must hold the bind key on the record. It clears the column and tombstones the person's marker and every key of the shape, current and retired, with `entity.holder-unbound` v1 (the caller as actor). It answers `boundedUnbind`: `{ ok: true, unbound: <principal> | null }`, a `coverage`, or `bind-not-declared`. vertical-auth mounts it for any vertical as `mountUnbindRoute(app, deps)`, at `POST /api/bindings/:entityType/:entityId/unbind` (403 naming the key, 404 for a type the scope does not bind).
- **Erasure unbinds.** An erasure reads every record bound to the erased subject, or that is the erased subject, before any module erasure runs. After the module hooks, in the same transaction, it releases each one: it takes the shape back from the person and clears the column where the row survived. A hook can still find rows by the binding column, and a record a hook or a `delete` removed is released all the same. The erasure writes no event for this, since an event naming the erased subject would be a new copy of it.
- **Kernel.** `entityBindingOf`, `unbindEntityHolderBounded`, `ENTITY_UNBIND_OPERATION`. `becomeMintCheck` takes an optional `bind`, and `exchangeCapability` an optional `allowed` dep (the checker's `check`, for the minter).
- **Not reached.** A person given a binding shape before the column was written (a legacy holder) is not named by it, so an unbind cannot reach them. A link the bind would now refuse still lists as `open` in `becomeLinkStates`: its state reflects the holdings digest, not the bind.
