The platform's entry module now carries the wire-signing verifier (RFC wire-signing, step 1), inert until a deployment is given key lists. No upload gives one any yet, so every deployed vertical is served exactly as before: the entry hands the vertical the very request it received and writes nothing new.

Once an upload gives a deployment key lists, the entry reads its state. In `dual` it serves a valid legacy credential as today and counts the envelope beside it, serves an envelope alone as the envelope says, and leaves a request neither proves to the vertical's own checks. In `signed-only` the envelope alone decides, with one fixed refusal for every reason. A fault of the version's own (no nonce store, or key lists that will not load) is counted in `dual` and the request handed on as it came, and answered with one fixed 503 in `signed-only`. Each judged request writes one `{ substrat: 'wire' }` line beside the invocation line.

No observability reader returns the wire line. `ObservabilityReader.recentLogs` now answers `{ events, incomplete }` rather than the bare list: `incomplete` is `true` when the read stopped before it could vouch that no line of the window is missing (the Cloudflare reader's bounds on the queries it makes to fill a page the wire line was taken out of). `GET /observability/logs` keeps its list body and says so in an `x-substrat-logs-incomplete: 1` header (`LOGS_INCOMPLETE_HEADER`); an incomplete list is not guaranteed to be a prefix of the window, and means only that there may be more or newer lines. An implementation of the reader returns the object.

`@substrat-run/contracts/wire-signing` gains the names a deployment's settings are read from (`WIRE_ROUTER_KEYS_VAR`, `WIRE_PLATFORM_KEYS_VAR`, `WIRE_AUDIENCE_VAR`, `WIRE_STATE_VAR`), `wireStateOf`, `wireEndpoint` (which kind and issuers an endpoint accepts, for the verifier and, later, the signers), `wireReplayOf` and `WIRE_REPLAY_FREE_CALLS` (each endpoint's stated replay policy: only a safe method or a listed read keeps no nonce), `decodeWireEnvelope` (the verifier's own decode, for reading claims before verifying them), a call's body given as a reader (`WireBodyReader`, read only once the signature, audience, time, method and target have passed), and the line's grammar (`WireVerificationLine`, `WIRE_OUTCOMES`, `WIRE_FAULTS`).
