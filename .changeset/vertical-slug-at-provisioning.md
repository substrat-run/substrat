An empty vertical slug was accepted at provisioning and then failed to parse when scopes were listed, and so were an empty kind and an empty name. Provisioning now takes the vertical a caller names in the registry's grammar (`verticalSlug`: lowercase letters, digits and hyphens, optionally prefixed by an owner slug and one `/`) and refuses anything else, an empty or whitespace-only string included; it refuses an empty or whitespace-only `kind` or `name` too, which used to be stored as given (an absent one still takes its default, and a value is stored as sent, not trimmed). Each refusal is `validation_failed` naming its field. The rules are held in `resolveScopeRecord`, which both adapters' `provisionScope` call, and at the edges that feed it: the `POST /scopes` body, the tenant-provisioner payload (`provisionTenantPayload.instance.vertical` and `.name`) and the sibling payload (`provisionSiblingPayload.name`). One new contracts schema, `scopeText`, is the kind and name rule in every one of those places. A null or absent vertical still means no vertical.

A copy is not a caller naming a vertical: `ProvisionScopeInput.verticalSource` is `'input'` by default, and `'copy'` on the paths that re-provision with an existing scope's own stored vertical (a snapshot, in both adapters' `snapshotScope` and the snapshot route, and a sibling scope). A copy takes that stored value as the directory reads it (non-empty), so a scope stored before the grammar was held here, with a vertical such as `Todo`, is still snapshotted and given siblings as before. No request body carries `verticalSource`.

A `provision-tenant` or `provision-sibling` platform request whose input cannot be provisioned is now settled `failed` at once, attributed `validation_failed`, instead of being retried each pass up to the attempt ceiling: a payload that does not parse (the fields named), and an input the provisioning would refuse. A `provision-tenant` request checks its whole input (the tenant and scope ids, the tenant it would create, the scope it would provision) before it writes anything, so such a request creates no tenant and grants nothing.

One directory row that does not read as a scope no longer stops a `runPlatformSweep` pass. `HostAdmin.listScopesReadable` is a new optional read that answers `listScopes`'s rows, except that a row which does not parse is returned in `unreadable` by its ids and the names of the fields that failed. Both adapters implement it through the kernel's new `readableScopes`. The sweep reads the directory through it, steps over such a row in every phase (the connector landing step and the router-kicked cross-vertical run included), and names it once per pass in `errors` as `scope-row` (at most twenty, then one line saying there are more). `listScopes` itself is unchanged and stays strict, and so does the default tenant reap, which clears the tenant's directory afterwards. An archived scope whose row does not read is therefore stepped over by the archived-scope reap and stays archived, named once per pass, until its row is corrected. `reconcilePendingHostnames` reads the dead scopes the same way: such a row still counts as dead, its hostnames are orphaned, and it is named in the result's `unreadableScopes` with its tenant, at most `UNREADABLE_SCOPE_ROWS_NAMED` (the sweep's cap, now exported) with the rest counted in `unreadableScopesUnnamed`. `unreadableScopeRowContractSuite` and `storedVerticalCopyContractSuite` hold both adapters to this.
